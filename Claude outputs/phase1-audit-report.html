3. Architecture

Clean layered separation: API → Services → Models
Strategy pattern for OCR engines (pluggable)
Storage abstraction (local / MinIO / S3)
Async DB via SQLAlchemy 2.0 + asyncpg
Pipeline is pure logic — no DB imports
Celery for background processing with Redis

Architecture is solid. No circular imports, clear dependency direction, and the pipeline's separation from persistence makes it independently testable.

4. Database & Migrations

16 tables across 6 model files — well-normalized
UUID primary keys, TimestampMixin across all models
FK constraints with CASCADE on all document-child joins
No Alembic version files — must generate initial migration

Alembic is configured (alembic/env.py exists with correct imports) but the versions/ directory is empty. Run alembic revision --autogenerate -m "initial" to generate the baseline migration before first deployment.

6. OCR & Processing Pipeline

Tesseract (primary) + EasyOCR (fallback) with auto-switch
Smart preprocessing — skips clean documents
Language detection via Unicode script + statistical analysis
Layout analysis: text blocks, tables, stamps, columns
PDF pages now yielded lazily (memory-safe)
Engine-level fallback with combined error reporting

The pipeline is well-structured and all the correctness bugs (deskew direction, language mapping, bounding box merging) are now fixed. Hindi/Marathi disambiguation now delegates to statistical detection.
